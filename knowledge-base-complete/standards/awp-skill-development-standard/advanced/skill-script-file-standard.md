# Script File Standard

> **Output**: Every executable script under `scripts/` (Python/Node/Deno/Shell). Each Skill has one `scripts/` directory.
> **Responsibility**: Define multi-runtime script structure, execution strategy, HTTP call rules, and credential loading.
>
> **About the examples**: The code examples in this document are general templates for any HTTP API service. Replace the URL, arguments, and authentication method in real use.

---

## 0. Design Principles

| Principle | Description |
|------|------|
| ✅ **Zero context cost** | A script runs through Bash. Its code does not enter the context window; only its output uses tokens. |
| ✅ **Determinism first** | Use scripts for deterministic work such as collection and conversion. Use a SubAgent for judgment. |
| ✅ **Solve, don't punt** | Solve problems inside the script. Do not throw errors back to the conversation for the user to handle. |

## 1. Directory Role

**Position**: Holds executable scripts, mainly Python, with support for several runtimes.

**Location**: `scripts/`

> **Key efficiency rule**: When a script runs through Bash, **the script code never enters the context window**. Only the **output** uses tokens. This makes a script more efficient and dependable than asking Claude to generate equivalent temporary code.

**Content types**:
- Data collection scripts
- Format conversion scripts
- Merge and processing scripts
- Shared modules (`shared/`)
- Scripts for other runtimes (`node/`, `deno/`, `bun/`, `shell/`)

**Do not put here**:
- Prompt templates → `reference/prompts/`
- Step documents → `workflow/`
- Configuration files → `config/`

## 2. Credential Loading

> Full credential-format definition, including Markdown tables and four authentication types → `skill-credential-file-standard.md` §2.
> Two-mode loading with the L0/L1/L2 three-level fallback → `skill-credential-file-standard.md` §3.
> This section lists only the **implementation rules for loading credentials in scripts**.

- Load through `shared/_cred.py:load_cred()` for one three-level fallback.
- Do not refer directly to a knowledge-base path from a script.
- Do not parse `*.json` / `*.env` / `*.yaml`; credentials use Markdown.
- Parsing regex: `\|\s*{key}\s*\|\s*` `` ` `` `([^` `` ` `` `]+)` `` ` ``

**Python example**:

```python
from shared._cred import load_cred

# Simple use: reads the "API Key" field by default
token = load_cred("example-api")
base_url = load_cred("example-api", "Base URL")

# OAuth1 (Twitter)
api_key = load_cred("twitter-api", "API Key")
bearer = load_cred("twitter-api", "Bearer Token")
```

## 3. scripts/ Directory Structure

> Full Skill directory structure → `../skill-core-file-declaration.md` §2. This section defines only the internal organization of scripts/.

```
scripts/
├── python/                   # Python runtime (primary)
│   ├── *.py                  # Python scripts
│   ├── shared/               # Shared modules
│   │   ├── __init__.py
│   │   ├── workflow.py       # Run-directory management
│   │   └── DATA_PATHS.md     # Data-path rules
│   ├── pyproject.toml        # Dependency configuration (optional)
│   └── uv.lock               # Dependency lock (optional, recommended)
├── node/                     # Node.js runtime (optional)
│   ├── package.json
│   ├── pnpm-lock.yaml
│   └── *.mjs
├── deno/                     # Deno runtime (optional)
│   ├── deno.json
│   └── *.ts
├── bun/                      # Bun runtime (optional)
│   ├── package.json
│   └── *.ts
└── shell/                    # Shell scripts (optional)
    └── *.sh
```

**Design rules**:
1. **Separate directory per runtime** - Each language manages its own dependencies.
2. **Python is primary** - ⚪ Prefer it, but put it under `python/`.
3. **Create only when needed** - Create only directories the Skill uses.
4. **Keep runtime entities outside** - `.venv`, `node_modules`, model weights, and SDK caches are not Skill source files.

**Runtime support matrix**, kept in sync with `skill-platform-constraint-limits.md`:

| Runtime | State |
|--------|------|
| Python | Supported |
| Node.js | Supported |
| Deno | Supported |
| Bash | Supported |
| Bun | Experimental |

## 4. Script vs. SubAgent

**Core question**: Does the operation require LLM understanding, judgment, or creation?

| Executor | Use | Why |
|--------|---------|---------|
| **Script** | Deterministic operations: collect / batch / merge / convert / upload | Dependable, retryable, no LLM dependency |
| **MCP** | Web search; choose freely, see §13 | Live data, low development cost |
| **SubAgent** | Intelligent operations: understand / evaluate / generate / decide | Requires LLM understanding and creation |

> **The 1M era**: Choose an executor based on the **nature of the task**, not context cost. With 1M, context cost is no longer the key decision factor.

> **Full rule**: See skill-step-document-standard.md §3.2 for executor choice and skill-step-document-standard.md §7 for the preparation SubAgent pattern.

## 6. Python Script Standard

### 6.1 Basic Structure

| Element | Rule |
|------|------|
| Entry | `argparse` + required `--run-dir` argument |
| Return | `print(json.dumps({"ok": True/False, ...}))` |
| Exit code | `sys.exit(0 if ok else 1)` |
| Exception | Catch with try/except and truncate err to 100 characters |
| Order | docstring → constants → core functions → entry |

### 6.2 Return Format

A script returns JSON in the form `{"ok": true/false, ...}`. Full field definitions → `skill-step-document-standard.md` §8.

```json
{"ok": true, "count": 150, "output": "step01-collect/data.json"}
{"ok": false, "err": "API rate limit exceeded"}
```

## 8. HTTP API Call Standard

### 8.1 Core Rules

| Rule | Description |
|------|------|
| Script independence | Code inside a script must not call MCP; the Skill workflow may use MCP |
| Use the standard library | Prefer urllib; httpx is optional |
| Timeout control | ✅ A timeout is required; standard range: 30–120 seconds |
| Error handling | Retry 5xx with exponential backoff; do not retry 4xx |

### 8.2 Basic Request Pattern

Use `urllib.request` + `Bearer {api_key}` + the `timeout` argument. For GET, build arguments with `urlencode`. For POST, encode the body as `application/json`.

### 8.3 Retry and Exponential Backoff

Use exponential backoff: `delay = base_delay * (2 ** attempt)`. Raise 4xx directly with no retry. For 429, read the `Retry-After` header and wait. Retry 5xx / timeout, three times by default.

### 8.4 Cursor Pagination

Loop over requests, pass the cursor argument each time, and accumulate the data field until `next_cursor` is empty.

### 8.5 Status-Code Handling

| Status Code | Meaning | Handling |
|--------|------|----------|
| 200–299 | Success | Parse the response |
| 400 | Invalid arguments | Do not retry |
| 401 | Authentication failed | Do not retry |
| 403 | Insufficient permission | Do not retry |
| 404 | Resource does not exist | Do not retry |
| 429 | Too many requests | Read Retry-After and retry |
| 500–599 | Server error | Retry with exponential backoff |

## 9. Dependency Declaration Standard

### 9.1 Python: Prefer PEP 723 for a Simple Script

For a single-file script with few dependencies, prefer PEP 723 inline metadata to reduce setup cost:

```python
# /// script
# requires-python = ">=3.12"
# dependencies = [
#   "httpx>=0.27,<1",
# ]
# ///
```

Run:

```bash
uv run scripts/python/collect.py --run-dir {run_dir}
```

When full reproducibility is needed, create a script lockfile:

```bash
uv lock --script scripts/python/collect.py
```

### 9.2 Python: Use pyproject.toml for Complex Scripts

```toml
[project]
name = "awp-skill-name"
requires-python = ">=3.12"
dependencies = [
    "httpx>=0.27",
]

[project.optional-dependencies]
dev = ["pytest>=8.0"]
```

A complex script must commit `pyproject.toml`; committing `uv.lock` is recommended. Runtime prepares the virtual-environment entity under `~/.awp/runtime/envs/skills/{skill-name}/...`. Do not commit it to the Skill directory.

### 9.3 Node.js: Use package.json + pnpm-lock.yaml

A Node script declares dependencies in `package.json`; committing `pnpm-lock.yaml` is recommended. Runtime prepares `node_modules` under `~/.awp/runtime/envs/skills/{skill-name}/...`. Do not commit it.

### 9.4 Forbidden

| Forbidden | Reason |
|------|------|
| requirements.txt | uv uses pyproject.toml |
| pip install | Use uv sync |
| pip freeze | Use uv pip compile |
| Commit `.venv` | It does not work across platforms and pollutes the main Skill library |
| Commit `node_modules` | It is large and platform-specific |

### 9.5 Common Commands

```bash
uv run scripts/python/xxx.py        # Run one PEP 723 script
uv sync --project scripts/python    # Prepare dependencies for a pyproject project
uv run --project scripts/python python xxx.py
pnpm --dir scripts/node install --frozen-lockfile
```

Call Runtime first before production execution:

```bash
python {skill_dir}/scripts/doctor.py --deep
python {skill_dir}/scripts/doctor.py
python {skill_dir}/scripts/prepare.py --profile standard
```

## 10. Main Agent Script Calls

### 10.1 Invocation

```python
# Call the collection script
Bash(
    command="cd {skill_dir}/scripts/python && uv run python collect.py --run-dir {run_dir} --hours 48",
    description="Run the data collection script",
    timeout=120000
)

# Call the batching script
Bash(
    command="cd {skill_dir}/scripts/python && uv run python batch.py --run-dir {run_dir} --batch-size 30",
    description="Run the data batching script",
    timeout=60000
)
```

### 10.2 Key Arguments

| Argument | Description |
|------|------|
| `cd {skill_dir}/scripts/python` | Change to the Python script directory so pyproject.toml takes effect |
| `uv run python` | Run in the virtual environment managed by uv |
| `--run-dir` | Run directory: `{run_dir}/` |
| `timeout` | Timeout in milliseconds; reference range: 60000–120000 |

### 10.3 Invocation Flow

```
Main Agent runs Step 01
    │
    ├─ 1. Bash: cd {skill_dir}/scripts/python && uv run python collect.py ...
    │       └─ Returns: {"ok": true, "count": 150, "output": "step01-collect/data.json"}
    │
    ├─ 2. Parse JSON and confirm ok=true
    │
    ├─ 3. Read: {run_dir}/step01-collect/data.json
    │
    ├─ 4. Update state/progress.json
    │
    └─ 5. Continue to Step 02
```

## 11. Multi-Runtime Scripts

### 11.1 Design Rules

| Principle | Description |
|------|------|
| **Separate directory per runtime** | Put each language in its own directory: python/, node/, and others |
| **Python is primary** | ⚪ Prefer it and put it in `scripts/python/` |
| **Create only when needed** | Create only directories that are actually used |
| **Shared return format** | Every runtime returns `{"ok": true/false, ...}` |

### 11.2 Runtime Selection Guide

| Case | ⚪ Preferred Runtime | Reason |
|------|-----------|------|
| Data processing, API calls | Python | Large ecosystem |
| Requires a specific npm package | Node.js | Unique npm ecosystem |
| Type safety + simplicity | Deno/Bun | Native TypeScript |
| Batch system commands | Shell | Calls system commands directly |
| High-performance IO | Bun | Very fast file IO |

### 11.3 Other Runtimes

Node.js / Shell scripts follow the same standard: a `--run-dir` argument + a JSON return in the form `{"ok": true/false, ...}`. Follow the structure of the Python template in §6.

## 12. Mixed Execution Flow

A typical workflow mixes scripts, MCP, and SubAgents:

```
Step 1: Collect data    → Script or MCP (see §12)  collect.py / brave_web_search
Step 2: Batch data      → Script (zero context)    batch.py
Step 3: Evaluate content → SubAgent (needs LLM)    Task(...)
Step 4: Merge results   → Script (zero context)    merge.py
Step 5: Upload storage  → Script (zero context)    upload.py
Step 6: Send notice     → Script (zero context)    notify.py
```

**Benefits of the mixed pattern**:

| Dimension | All-SubAgent Pattern | Mixed Pattern |
|------|----------------|---------|
| Reliability | Depends on the LLM for deterministic operations | Scripts make deterministic operations accurate |
| Retryability | After an Agent fails, it must understand the context again | A failed script can be retried directly |
| Debugging | LLM behavior is unpredictable | Script behavior is predictable and can be logged |
| Context use | Higher, but controlled with 1M | Lower |

> **Selection rule**: Use a script for deterministic operations, with reliability first. Use a SubAgent for intelligent operations, with ability first. The 1M context does not change this rule.

## 13. Collection Operations

**Core rule**: The Skill designer may choose freely between script and MCP collection.

### 13.1 Script Collection

| Advantage | Description |
|------|------|
| Zero context | Returns only status JSON |
| Controlled rate limits | Precisely control concurrency and intervals |
| Retry mechanism | Exponential backoff |

```python
Bash("cd {skill_dir}/scripts/python && uv run python collect.py --run-dir {run_dir}")
```

### 13.2 MCP Collection

| Advantage | Description |
|------|------|
| Live results | Gets the latest web information |
| LLM understanding | Filters relevant content directly |
| No script needed | Low development cost |

**Available tools**: `brave_web_search`, `brave_news_search`, `exa`, `WebSearch`

**Rate-limit rule**: Call in series, wait at least 2 seconds, and do not run calls in parallel.

### 13.3 Comparison

| Dimension | Script | MCP |
|------|------|-----|
| Context cost | Zero | Medium |
| Development cost | High | Low |
| Rate-limit control | Exact | Depends on rules |

## 15. Practices

| Practice | Description |
|------|------|
| **Single responsibility** | Each script does one thing |
| **Idempotency** | The same input produces the same output |
| **Error isolation** | A script failure does not affect the main Agent |
| **Short logs** | Output only status JSON |
| **Timeout control** | Set a sensible timeout |
| **Solve, don't punt** | The script solves the problem instead of handing it to Claude |
| **No magic numbers** | Every constant has a comment that explains it |

### 15.1 Solve, Don't Punt

> **Source**: Anthropic's official Skill practices.

A script should handle error conditions instead of asking Claude to guess:

```python
# ❌ Punt it to Claude
def process_file(path):
    return open(path).read()  # FileNotFoundError → Claude guesses

# ✅ Solve it here
def process_file(path):
    try:
        return open(path).read()
    except FileNotFoundError:
        print(f"File {path} not found, creating default")
        open(path, "w").write("")
        return ""
    except PermissionError:
        print(f"Cannot access {path}, using default")
        return ""
```

### 15.2 No Magic Numbers

Every configuration value needs a comment explaining the reason:

```python
# ✅ Self-documenting
REQUEST_TIMEOUT = 30   # Standard HTTP request timeout: 30 seconds
MAX_RETRIES = 3        # Most intermittent failures clear by the second retry
BATCH_SIZE = 30        # Balances API rate limits and processing speed

# ❌ Magic numbers
TIMEOUT = 47           # Why 47?
RETRIES = 5            # Why 5?
```

### 15.3 Fully Qualified MCP Tool Names

An MCP tool reference must include the server prefix. Without it, the result is "tool not found." Use one of two forms:

| Case | Format | Example |
|------|------|------|
| Telling Claude to use a tool in SKILL.md / Prompt prose | `ServerName:tool_name` | `Use the BigQuery:bigquery_schema tool` |
| frontmatter `allowed-tools` list / code | `mcp__server__tool` | `mcp__github__create_issue` |

When several MCP servers are available, Claude cannot locate a tool by its tool name alone. Name the server.

## 16. Forbidden Items

| Forbidden | Reason |
|------|------|
| Call an LLM for a deterministic operation | Pure data processing and format conversion do not need an LLM. Intelligent judgment such as translation or evaluation may call one. |
| Output large logs to stdout | Pollutes the return value |
| Make semantic decisions in a script | Give decisions requiring semantic understanding or subjective judgment to an Agent. Deterministic logic such as retry, validation, and branching may stay in the script. |
| Hardcode paths | Pass them as arguments |
| Silently download a model or create a long-lived environment | Runtime `prepare` must do this in one place |
| Write directly to `/tmp` as persistent cache | A temporary directory cannot be recovered, and state is lost after restart |
| Commit `.venv` / `node_modules` / model weights | They do not work across platforms and pollute syncing and distribution |

## Checklist

**Script files**:
- [ ] Scripts live in the scripts/ directory.
- [ ] Credentials load through `shared/_cred.py:load_cred()`.
- [ ] The script handles errors and does not throw them back to the conversation: Solve, don't punt.

**HTTP requests**:
- [ ] HTTP requests set a timeout of 30–120 seconds.
- [ ] 5xx/timeouts retry with exponential backoff; 4xx does not retry.

**Tools and dependencies**:
- [ ] MCP tools include the server prefix: `Server:tool` in prose, `mcp__server__tool` in allowed-tools/code.
- [ ] Python scripts use PEP 723 or pyproject.toml + uv.
- [ ] Complex dependencies include a committed lockfile.
- [ ] Dependencies are declared in pyproject.toml or PEP 723; requirements.txt is forbidden.
- [ ] `.venv`, `node_modules`, and model weights are outside the Skill directory.
- [ ] Script entry points are included in the Step00 preflight check.
- [ ] Scripts that need an environment or model pass Runtime doctor/prepare first.
- [ ] It passes `../../awp-meta-authoring-standard/std-style-language-contract.md`: three-layer language contract / remove jargon / formalize speech / fidelity, clarity, and grace.
